# 평정용 24문항 설계 (초등 12 · 중등 12)

준거 4개·지표 13개(델파이 전 시안)에 맞춘 평정용 디지털 평가 문항이다.

> **지표 통합(델파이 전 시안):** 연구자도 가르기 어려웠던 '정보 선별'과 '장식 절제'를 **'불필요 요소 배제'**(풀이와 응답에 필요하지 않은 정보나 장식 요소는 제시되지 않는다)로 합쳤다. 지표 id 는 I01 을 쓰고 I02 는 비워 둔다(다른 지표 id 는 그대로). 이에 따라 필요성 준거의 결함 문항 2개는 '불필요 요소 배제'(캐릭터)와 '반복 최소화'(표를 그대로 옮긴 막대그래프)가 맡는다.
공통 단서: 모든 지표는 해당 문항이 측정하려는 능력과 응시 학습자에 비추어 판단한다.

- **세트 2개:** 초등 세트(E01~E12)와 중등 세트(M01~M12). 교사는 기본 정보의 '근무 학교급' 답에 따라 한 세트(12문항)만 평정한다.
- **세트 구성:** 세트마다 결함 문항 8개(준거별 2개, 서로 다른 지표 8개) + 결함 없는 문항 4개.
- **두 세트의 관계:** 같은 지표 8개를 같은 결함 방식으로 다룬다. 내용만 학교급에 맞게 다르므로 학교급끼리 견줄 수 있다.
- **결함 원칙:** 한 문항에는 대상 지표 하나의 결함만 넣고, 결함 없는 문항은 13개 지표를 모두 충족한다.
- **예시와의 관계:** 결함 사례는 준거표의 결함 예시와 원리는 같고 사례는 다르다.

## 결함 켜고 끄기

- **평정 조사:** `Code.gs`의 `DEFECTS.<문항 id>.on`을 바꾼다. 바꾼 뒤에는 `toolVersion`을 바꾸고 `index.html`의 `SERVER.toolVersion`도 똑같이 바꾼다.
  - 참여자마다 실제로 본 결함 상태가 시트(`participants.defects`, `ratings.defect_on`)에 남는다.
- **미리보기:** `items/config.js`의 `defects`를 바꾸거나, 주소 뒤에 다음을 붙인다.

| 주소 뒤에 붙일 것 | 내용 |
|---|---|
| `?set=E` / `?set=M` | 초등 / 중등 세트 |
| `&item=5` | 그 세트의 5번 |
| `&clean=1` | 결함 모두 끄기 |
| `&off=E03,M05` / `&on=…` | 그 문항의 결함만 끄기 / 켜기 |
| `&panel=1` | 문항 화면 밖에 연구자 설정 칸 열기 |

## 화면 구성

실제 디지털 평가 화면에 맞췄다(확인평가형 화면 참고).

- 1280×800 고정 캔버스(11인치 태블릿)를 창에 맞춰 통째로 확대·축소한다.
- **플랫폼 공통 요소(평정 대상 아님):**
  - 위쪽 띠: '확인평가', 교과, 학교급, [연습장]
  - 아래쪽 띠: 문항 번호(‹ 1 2 … 12 ›), [정답 확인]
  - 모두 실제로 눌린다.
- **평정 대상 영역:** 가운데 흰 칸 하나.
- **문항 모양:**
  - 문두 앞에 남색 네모 문항 번호가 붙는다(세트 안에서 보이는 차례). 근거 요소 번호(빨간 원)와 겹치지 않게 모양을 달리했다.
  - 선택지는 원 번호 목록이다(테두리 상자 없음, 줄 높이 54px).
- **배치:**
  - 국어(지문 있음): 왼쪽 칸에 지시문 "다음 글을 읽고, 물음에 답하세요."와 지문, 세로 구분선, 오른쪽 칸에 번호·문두·응답. 긴 지문은 지문 칸 안에서만 스크롤된다.
  - 그 밖의 교과: 한 단으로 문두 → 그림·자료 → 응답. M03만 그림과 잇기 칸을 나란히 둔다.
- **안내 문장:** 선택형·단답형에는 따로 두지 않는다(원 번호, 테두리 있는 입력 칸으로 응답 방식이 드러남). 끌어 놓기·선 잇기에는 조작 방법 한 줄을 둔다.
- **조작:** 모든 문항에서 같은 코드로 정상 동작한다. 끌기와 '누르고 칸 누르기'를 모두 지원하고, 놓은 카드는 다시 옮길 수 있으며, 선을 누르면 지워진다. 플랫폼 기능 수준의 결함은 없다.
- **자동 점검:** 24문항 모두 결함 켠 판·끈 판에서 한 화면에 들어오고, 끝까지 풀어 정답 판정이 맞는다.

## 평정 방식 (교사의 적용 가능성 검토)

- 교사는 문항을 직접 푼 뒤, 문항마다 지표 13개를 **'충족 / 미충족 / 해당 없음'** 중 하나로 판단한다(점수별 기술문 없음).
- 평정 칸 위쪽의 준거 칸(필요성·명료성·통합성·조작)을 눌러 준거별 지표를 오가며 판단한다.
- **'미충족'의 근거:**
  - '미충족'을 고르면 문항 화면 위에 **빨간 원 요소 번호**가 나타난다. 번호는 평정할 때만 보이고, 풀이 화면은 학생 화면 그대로다.
  - 교사는 근거가 된 요소를 하나 이상 고른다. 메모는 선택이다.
  - 목록에 없는 것을 근거로 삼으려면 '그 밖의 요소'를 고르고 메모를 적는다(이때 메모는 필수).
- **근거 요소의 정의:** 문항 화면에서 `data-el`로 표시한 요소다.
  - 문두, 지시문, 지문·그림·표·자료, 선택지·답 칸·선 잇기 칸, 카드, 카드 놓는 칸, 응답 방법 안내
  - 그리고 결함 요소(더 알아보기 상자, 캐릭터 그림, 지문 보기 단추)
- **판단 조건:** 결함 문항의 수와 위치는 알리지 않고, 문항 제시 순서는 교사마다 무작위다.
- **마지막 개방형 질문:** 판단하기 어려웠던 지표와 그 이유, 준거와 지표의 활용에 대한 의견.

## 산출 지표 (Code.gs `summarize()`)

`Code.gs`의 `DEFECTS.elements`에 결함 문항마다 **의도한 결함 요소**를 정해 두었다. 교사가 고른 근거 요소를 이것과 대조해 판단을 나눈다.

| 판단 유형 | 기준 |
|---|---|
| 결함 탐지 | '미충족'의 근거에 의도한 결함 요소가 있다 |
| 과잉 판단 | '미충족'의 근거에 의도한 결함 요소가 없다(결함 없는 문항의 '미충족'은 모두 여기) |
| 준거 일치 | 결함을 탐지한 평정이 의도한 지표에서만 판단했다 |
| 준거 혼동 | 결함을 탐지했으나 다른 지표에서 판단했거나 여러 지표에서 중복 판단했다 |

| 지표 | 계산 |
|---|---|
| 결함 탐지율 | 결함 탐지가 한 번 이상 있는 평정 ÷ 결함 문항 평정(교사 × 결함 문항) |
| 준거 일치율 | 준거 일치 ÷ 결함을 탐지한 평정. 준거 수준(같은 준거 안의 지표면 일치)도 함께 계산 |
| 과잉 판단율 | 과잉 판단 수 ÷ '해당 없음'을 뺀 전체 지표 판단 수 |

- `summarize()`를 실행하면 `summary` 탭에 위 비율을 적는다. 단위는 전체·학교급·교사·문항별이고, 지표별 과잉 판단도 함께 적는다.
- 미리보기 응답(test)은 뺀다.
- **판단을 고친 경우:** '그 밖의 요소(메모)'를 고른 판단은 `judgments` 탭에 `needs_review = TRUE`로 표시된다. 연구자가 메모를 읽고 `judgment_type`을 고친 뒤 `summarize()`를 다시 실행하면 고친 값으로 다시 센다.
- **섞인 근거:** 의도한 결함 요소와 다른 요소가 함께 섞인 근거는 결함 탐지로 세고, 그 수를 따로 적는다(`hits_other`, '섞인 근거 수'). 과잉 판단에 넣을지는 연구자가 정한다.

## 지표별 결함 방식 (두 세트 공통)

| 준거 | 지표 | 결함 방식 | 결함 예시와 다른 이유 | 다른 지표에 걸리지 않는 이유 |
|---|---|---|---|---|
| 필요성 | 불필요 요소 배제 | 문두 옆에 문두 글자보다 시각적 무게가 큰 정지 캐릭터(약 170px). 지문과 관련된 모습(개미·고래)이지만 내용 정보는 없음 | 예시는 흥미 유발 문장과 움직이는 배경 효과, 이 문항은 정지한 크기·무게로 눈길을 끄는 그림 | 글·말풍선이 없어 새 정보가 없고(반복 아님), 응답이 화면 안에 그대로 있다 |
| 필요성 | 반복 최소화 | 표의 수치를 그대로 옮긴 막대그래프를 표 옆에 둠. 기준선이 없고 값이 기준 근처라 표 이상의 도움이 없음 | 예시는 지문을 옮긴 만화, 이 문항은 표를 옮긴 그래프 | 표와 같은 정보라 '화면에 이미 있는 정보의 되풀이'로 가를 수 있다. 막대는 한 가지 색이라 색 구분 문제가 없다 |
| 명료성 | 색 외 구분 단서 | 그림 요소를 색으로만 구분하고, 문항도 색 이름으로만 가리킴. 끄면 ㉠㉡… 기호가 붙음 | 예시는 데이터 그래프 계열, 이 문항은 설명 그림(지층·화살표) | 색 대비가 충분하고 특정 요소만 강조하지 않는다. 그림과 응답이 나란히 있다 |
| 명료성 | 핵심 정보 강조 | 문두 어구마다 굵게·색·밑줄·형광을 서로 다르게 넣어 핵심 조건이 묻힘. 끄면 핵심 조건만 굵은 밑줄 | 예시는 강조가 없거나 정답에만 붙은 경우, 이 문항은 과잉 강조 | 대비 4.5:1 이상, 글자 크기가 같고, 응답에는 강조가 없다 |
| 통합성 | 지문·자료 참조 | 지문은 [지문 보기] 팝업으로만 보이고, 팝업이 **문두 아래부터** 응답 영역을 덮음. 문두는 가리지 않음 | 예시는 탭 전환, 이 문항은 같은 화면 위에 덮이는 겹침 | 문두는 늘 보인다. 지문 열기·닫기는 참조 행동이라 응답 조작이 아니다 |
| 통합성 | 관련 정보 근접 배치 | 비교해야 할 두 자료를 왼쪽 위·오른쪽 아래로 떨어뜨림. 끄면 한 자료 상자에 나란히 | 예시는 그래프와 범례, 이 문항은 서로 비교할 두 자료 | 스크롤 없이 한 화면에 있고, 자료 상자마다 테두리와 이름이 있다 |
| 조작 | 응답 방식 인지 | '답' 상자 속 괄호 `(   )`가 입력 칸인데 본문 괄호와 똑같이 보이고 안내가 없음 | 예시는 선 잇기의 잇는 방식, 이 문항은 단답형의 입력 위치 | 응답 영역 경계는 뚜렷하다. 누르면 바로 입력되고(1단계), 입력 글자는 즉시 보인다 |
| 조작 | 응답 결과 표시 | 칸에 놓은 카드가 글자 없는 작은 점(●)으로만 남음 | 예시는 칸을 벗어나 보이는 위치 문제, 이 문항은 칸 안에서 내용이 안 보이는 문제 | 누르는 범위가 52×52px라 크기를 충족한다. 다시 옮길 수 있고 안내도 있다 |

## 중등 세트 (M) — 중학교 교과 수준

**분포 (세트마다)**
- 교과: 국어·수학·과학·사회 각 3문항(교과마다 결함 2 + 결함 없음 1)
- 응답 형식: 선택형·단답형·끌어 놓기·선 잇기 각 3문항
- 준거마다 결함 문항 2개는 응답 형식이 서로 다르다.

`Code.gs`의 `checkConfig()`가 이 조건(세트당 12문항, 준거별 결함 2개, 지표 겹침 없음, 두 세트의 지표가 같음)을 확인한다.

🖼 = Codex 그림 대상. 지금은 임시 SVG가 들어가 있다.

## 시트 기록 (Code.gs)

| 탭 | 기록 |
|---|---|
| `participants` | 교사 한 명당 한 줄. `level`(E/M), 기본 정보, `item_order`, `defects`(본 결함 상태), 마지막 개방형 응답(`hard`, `use`) |
| `judgments` | **지표 판단 한 개당 한 줄**(교사 × 문항 × 지표 13개). 아래 표 참고 |
| `items` | 문항 한 개당 한 줄. 아래 표 참고 |
| `summary` | `summarize()` 결과 |
| `codes` | 참여 코드. `item_order`에 두 세트 순서를 `E:…\|M:…`로 저장 |

**`judgments` 탭의 열**

| 열 | 뜻 |
|---|---|
| `defect_on` | 이 교사에게 이 문항이 결함 문항이었는가 |
| `target_criterion`·`target_indicator_id`·`target_elements` | 의도한 결함의 준거·지표·요소 |
| `judgment` | 충족 / 미충족 / 해당 없음 |
| `evidence_keys`·`evidence` | 근거 요소의 key, 화면 번호와 이름 |
| `note` | 교사 메모 |
| `judgment_type` | 충족 / 해당 없음 / 결함 탐지 / 과잉 판단 |
| `hits_defect`·`hits_other` | 근거에 의도한 결함 요소 / 그 밖의 요소가 있는가 |
| `on_target_indicator`·`on_target_criterion` | 의도한 지표·준거에서 판단했는가 |
| `needs_review` | 메모를 보고 분류를 확인해야 하는가 |

**`items` 탭의 열**

| 열 | 뜻 |
|---|---|
| 조작 로그 | 본 시간, 풀이 시간, 조작 횟수, 지문 팝업·정답 확인·연습장 사용, 응답, 정답 여부 |
| 판단 요약 | `judged`·`na`·`unmet`·`over`·`mixed`·`review` |
| 탐지 결과 | `detected`, `detect_indicators`, `criterion_match`(일치/혼동), `same_criterion_only` |

## 기존 평정 화면의 결함 스위치 재점검

예전 `design.*` 스위치(문항 32화면용)는 새 문항에서 쓰지 않고, 그리는 코드도 `index.html`에서 걷어 냈다. 새 준거로 보면 다음과 같다.

| 기존 스위치 | 새 준거로 보면 |
|---|---|
| `smallChoices` | 가독성 — 결함 예시(작은 글자)와 같은 사례 |
| `noBorders` | 영역 구분 — 결함 예시(경계 없는 지문·선택지)와 같은 사례 |
| `stackpin`, `far` | 문두·응답 동시 제시 — 결함 예시(밀려나는 문두)와 같은 사례 |
| `decorSvg`(움직이는 별·캐릭터) | 장식 절제 — 결함 예시(움직이는 효과)와 같은 사례 |
| `decor: 'kid'`(말풍선 글) | 장식 절제와 정보 선별이 섞임 |
| `hideLines` | 응답 결과 표시와 수정 불가가 섞임 |
| `hierarchy: 'flat'` | 영역 구분·강조·가독성이 섞임 |
| `longPress` | 플랫폼 기능 수준 — 제외 대상 |
| `popup` | 지문·자료 참조 — 팝업이 문두까지 덮으면 문두·응답 지표와 섞임 |
